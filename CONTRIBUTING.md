# Contributing

Choose a challenge issue and comment with your intended approach and collaborators. Maintainers may assign participants; alternatives can run in parallel. Use the issue list initially: unassigned/open = available, assigned/open = exploring, linked open PR = ready for review, merged PR with evaluation = tested. A GitHub Project board is optional and is not provisioned by this kit.

Use a branch and pull request. Include the issue number, instructions to reproduce, test results, limitations, sources, and model/hardware details when applicable. Passing fixture checks establishes data shape only; it does not establish capability accuracy. Provide challenge-specific evaluations, including failures and unknown cases.

Maintainers review the evidence, privacy boundaries, interface compatibility, license compatibility, and acceptance criteria before merging. Avoid publishing an unreviewed model output as service guidance. Do not add dependencies to the shared environment without documenting and reviewing them.
